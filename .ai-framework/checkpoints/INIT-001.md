## Контроль и права
- Корневой AGENTS сохранён, новый раздел направляет к ENTRYPOINT; иных штатных agent-файлов в дереве не найдено. Конкретные настройки стороннего агента не менялись; требовать явное чтение AGENTS при новом чате.
- Новые источники только ядро, две конфигурации и этот checkpoint; старые документы дополнены ссылками, не заменены. Перенос core сверяется по Git blob SHA исходного ZIP.
- Локальный checkout GitHub недоступен из контейнера (DNS), поэтому реальная ветка и пути проверяются GitHub connector, Python структурный тест — на локальном зеркале путей, не полноценной копии репозитория. `--ready`/`--proposal` должны отказать при открытых темах; никакого фиктивного approval. `--run` Android not_run, поскольку окружения нет и не требуется в INIT; CI не изменять и не запускать вручную. Результаты структурной проверки и проверки дерева фиксируются отдельно в этом checkpoint после выполнения.
- Риски: не раскрывать секреты, не удалять рабочие данные, не менять ключи. Исходный base сохранён; отдельная ветка для review, без PR/merge/release, без автоматического запуска CI на ней по существующим branch filters.
- Следующий шаг: согласовать с владельцем границы MVP и ADR; снять PZ-01…04, подготовить проверяемое резюме в выбранном источнике решений, `verify.py --proposal`, получить явное подтверждение конкретной редакции, затем `verify.py --ready`. До этого AUDIT/PLAN/DOCS/TEST по разрешению, не DEVELOP. После review интегрировать изменения в рабочую ветку только с согласованием, сохраняя существующее состояние.
