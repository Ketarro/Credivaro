Samsung A30s остаётся открытым дефектом, точная причина неизвестна. Xiaomi 17 и PILOT 3 (Android 16, Doke OS 5) успешно устанавливаются через Telegram по сообщению владельца. Приоритет функционального развития после диагностики — первый слой защищённого постоянного хранения. Начать с [STORAGE-PREPARATION.md](docs/STORAGE-PREPARATION.md), сверить архитектурные решения PR #3 и фактические модели.
1. Проверить совместимые актуальные версии Room/KSP и поддерживаемого провайдера зашифрованного SQLite, условия лицензии, ABI/minSdk и интеграцию. Зафиксировать выбор в ADR. Не считать Android Keystore самостоятельным шифрованием Room.
2. Создать модуль БД, схему и экспорт схем, DAO, репозиторий, маппинг всех существующих типов и nullable значений; транзакции, валидация, история снимков, без destructive migration.
3. Реализовать жизненный цикл ключа: случайный секрет БД, защищённое обёртывание Keystore, обработка повреждения/утраты ключа без автоматического удаления данных. Не хранить ключи, реальные записи или секреты в git/logs.
4. Добавить JVM и инструментальные проверки (reopen, rollback, миграции, ошибочный ключ, отсутствие plaintext, backup/transfer). Только после успешной проверки подключить UI к репозиторию; если этап разделён на несколько alpha, явно отметить границы и не включать непроверенное хранилище для реальных данных.
5. Прогнать CI, получить подписанный APK, отдельно провести ручную проверку на устройстве. Не обещать, что Build 9 сразу закроет весь объём безопасности.
После хранения: платежи и сверка -> события/календарь -> уведомления -> аналитика и стратегии, с возможностью менять приоритеты по обратной связи.

## 6. Правила передачи работы
При начале работы: подключить GitHub, открыть этот файл, ROADMAP.md и AGENTS.md из указанной ветки, проверить HEAD/PR/CI, выбрать ID пункта карты и прочитать актуальные затронутые файлы. Не повторять уже пройденные этапы и не перезаписывать изменения владельца. Если состояние отличается от HANDOFF, сначала сверить и обновить контекст. Не force-push; обновление ветки с проверкой ожидаемого SHA.
CI: JDK 17, Gradle 8.13, SDK 36, :core:model:test :app:lintDebug :app:testDebugUnitTest :app:assembleDebug. Подписанная сборка только из доверенной ветки push/workflow_dispatch; сохранить существующий сертификат, не раскрывать/запрашивать ключ в чате и не использовать temporary-debug для обновления. Не менять секреты без разрешения.
После каждого существенного этапа и ручного теста обновлять ROADMAP.md, HANDOFF.md, историю итераций и отчёт проверки; пересчитать прогресс и запустить проверку карты. Указывать проверенный SHA, версию, статус CI, ссылку на артефакт, ограничения, следующее действие; не выдавать запланированное за сделанное. Документационный коммит не требует повышения versionCode, но текущий CI может запуститься и для него. Не публиковать скриншоты устройства и финансовые данные.
