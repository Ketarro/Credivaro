## Расширенное исследование UX — варианты для согласования, 2026-11-25
Источники: [Т-Банк — главный экран](https://www.tbank.ru/finance/blog/new-mb/), [Monefy — быстрый ввод](https://www.monefy.com/help-center), [Debt Payoff Planner — карточки/прогресс](https://www.debtpayoffplanner.com/), [Realbyte — календарь](https://help.realbyteapps.com/hc/en-us/articles/360046150874-Home-tab), [Monarch — настройка сводки](https://help.monarch.com/hc/en-us/articles/360058127551-Customizing-Your-Dashboard), [YNAB — запись операций](https://support.ynab.com/en_us/how-to-add-transactions-in-ynab-HyDwA_byi?mobile-help=true), [Android — layout/navigation](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns). Изучены публичные руководства, не проведено очное usability-тестирование конкурентов. Не копировать чужие активы.
A. «Сегодня»: главный экран задач (ближайшая известная дата, быстрые действия, короткий список); лучше при регулярных платежах. Не выводить просрочку/статус исполнения до реальной модели событий/сверки.
B. «Мой кошелёк»: карточки всех кредитов как главное рабочее пространство, фильтр типа/валюты и быстрый переход к записи; хорошо при небольшом числе обязательств, хуже при большом списке. Не требовать свайпа или карусели для доступа.
C. «План месяца»: календарь + список событий по дням, план и факт отдельно, платежи из события; нужен R05/R06, пока не включать неработающие вкладки.
Рекомендуется гибрид A+B сейчас, C после реализации календаря. Нижние разделы Главная / Кредиты / Настройки на текущем этапе (в будущем Главная / Кредиты / Календарь / Аналитика, настройки через явно подписанное действие; название «Кредиты» для всех типов требует согласования). Постоянная подписанная кнопка «Записать платёж» на главной/карточке; на главной выбрать обязательство, в карточке оно уже выбрано. Форма: сумма + дата по умолчанию сегодня в банковской зоне, явная валюта, необязательное распределение раскрывается, примечание опционально, кнопка «Сохранить запись», без имитации банковского перевода; подтверждение результата и быстрый переход в историю. Не подставлять сумму планового платежа без подтверждения; неизвестное распределение явно хранить, банковский снимок не менять. Для новой записи сначала тип, название, валюта и известный остаток (необязательно); дополнительные условия позже, без обязательного заполнения неизвестного. Карточка: Обзор/Платежи/Условия, edit/delete в меню; исправление/отмена платежа только после R04.04, неизменяемая история.
Целевые критерии UX (проектные цели, не измеренные результаты): создать форму кредита за 1 действие с главной; открыть форму платежа за 1 действие из карточки, за 1–2 с главной; от сохранения до видимой истории не более 1 действия; Back предсказуем, сохранять список/позицию, предупреждать о несохранённом вводе, не прерывать транзакцию; >=48dp, доступно одной рукой, RU/EN, большие шрифты и TalkBack; проверять на 1/5/20 синтетических обязательствах, нескольких валютах и неизвестных суммах. 5 пробных заданий без подсказки и замер действий/ошибок; не считать цели достигнутыми без тестов. Порядок: навигационная модель и быстрые действия, карточка/форма, затем correction UI и регрессия; календарь/аналитика в своих ROADMAP задачах. Build 13 только после согласования и проверки безопасной подписи/upgrade; Build 12 продолжает ручную приёмку. Никаких изменений исходников, схем, CI, статусов принятия или опубликованного релиза.
